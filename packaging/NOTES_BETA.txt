1.1.10-beta190 (beta channel) — PHP Harden can now lock the SITE FOLDER, not only the files in it. A file lock stops an existing file being overwritten; a folder lock stops a new one being created at all — which is how the 2026-09-08 takeover started, with a file simply ADDED at the top of a site by someone holding the account password. It is off unless ticked, offered per document root only (never an arbitrary directory, because "no new file may appear here" is only true and only explainable for a site's own top level), and the page states the cost as plainly as the benefit: the site itself can no longer create files there either, so it is wrong for a site that installs plugins into its own root. Uploads below the folder are unaffected. Every root is opened before protection runs and closed after, so a second run can never fail against the protection the first one applied, and both Unlock and Force Unprotect clear it — a folder left locked while the page says "released" would be exactly the false statement those actions exist to prevent. Also in this line: the 80x faster batched locking (beta189). Stable is 1.1.9.
